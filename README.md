# JANUS — руководство

**J**ournaled **A**pplication **N**etwork **U**sage **S**canner · by Tracewarden

JANUS отвечает на вопрос «какая программа на этой машине ходила в сеть, когда и сколько передала» в ситуации, когда обычных способов это узнать нет: на хосте не стоит Sysmon и EDR, аудит создания процессов отключён, а журналы событий либо пусты, либо обнулены обновлением. Такое типично для личных устройств, подрядчиков и машин дочерних организаций — то есть ровно там, где чаще всего и обнаруживается что-то интересное. Инструмент читает SRUM (`SRUDB.dat`) — базу, в которую Windows независимо от всяких политик аудита ведёт почасовой учёт трафика по каждому приложению за последние 30–60 дней, — и обогащает её данными из кустов реестра: часовым поясом машины, службами и задачами планировщика, датами установки программ, историей подключений к сетям и счётчиками ручных запусков из UserAssist. На выходе — ранжированный список процессов с пометками, почему каждый из них подозрителен: круглосуточная работа, симметричный трафик (признак транзитного прокси), перекос в отдачу (признак выгрузки), запуск из пользовательского каталога, совпадение с известными провайдерами проксивари и туннелей. Типовые сценарии применения: расследование инцидента с неизвестным сетевым соединением, поиск proxyware и residential-прокси, обнаружение несанкционированных VPN и туннелей, проверка гипотезы об утечке данных, определение механизма закрепления найденного ПО и восстановление хронологии — когда оно появилось на машине и когда перестало работать.

Проверен на Windows 11 24H2 (build 26100), Python 3.12.

---

## 1. Установка

```bash
pip install dissect.esedb python-registry
```

`python-registry` опционален: без него скрипт работает, но только по SRUM, без обогащения из реестра.

---

## 2. Что подать на вход

| Файл | Откуда | Обязателен |
|---|---|---|
| `SRUDB.dat` | `C:\Windows\System32\sru\` | **да** |
| `SYSTEM` | `C:\Windows\System32\config\` | нет |
| `SOFTWARE` | `C:\Windows\System32\config\` | нет |
| `NTUSER.DAT` | `C:\Users\<профиль>\` | нет |

## 3. Режимы

Заставка и цвета включаются только в интерактивном терминале. При перенаправлении вывода в файл или пайп они подавляются автоматически — в приложенных к тикету логах не будет ни ASCII-арта, ни escape-последовательностей.

Принудительное отключение: `--no-banner`, `--no-color`. Переменная окружения `NO_COLOR` тоже учитывается. На Windows 10+ обработка ANSI включается автоматически.

Цветовая схема:

| Цвет | Что означает |
|---|---|
| ярко-красный | поведенческий признак или совпадение со списком проксивари |
| жёлтый | совпадение со списком туннелей, запуск из пользовательского каталога |
| голубой | данные из реестра: служба, задача, автозапуск, пользователь |
| жирный шрифт | путь бинаря, у которого сработало три и более признаков |

### Общий отчёт

```bash
python janus.py SRUDB.dat
python janus.py SRUDB.dat --system SYSTEM --software SOFTWARE --ntuser NTUSER.DAT
```

Основной режим. Ранжирует приложения по числу сработавших признаков.

### Окно времени

```bash
python janus.py SRUDB.dat --system SYSTEM --window "2026-08-18 07:00" "2026-08-18 08:10"
```

Что было в сети в конкретный интервал. **Время задаётся в UTC.** С кустом SYSTEM в выводе появится колонка локального времени машины.

### Детализация по бинарю

```bash
python janus.py SRUDB.dat --system SYSTEM --software SOFTWARE --app winproxy
python janus.py SRUDB.dat --app openvpn
```

Подстрока ищется в пути, регистр не важен. Даёт первое/последнее появление, суточный профиль, соотношение трафика, привязку к службе/задаче/автозапуску.

### Персистентность (без SRUM)

```bash
python janus.py SRUDB.dat --system SYSTEM --software SOFTWARE --ntuser NTUSER.DAT --persistence
```

Автозапуск, службы, задачи планировщика, установленные программы, профили сетей, UserAssist. Полезно тем, что показывает софт, который в SRUM не попал из-за отсутствия сетевой активности.

Аргумент `SRUDB.dat` в этом режиме не читается, но позиционно обязателен — подставь любой существующий путь.

## 4. Как читать вывод

```
   SENT MB    RECV MB  часов   covr  APP
    1159.3     1119.8    644    99%  C:\program files\wproxy\winproxy\winproxy.exe
                                      ^ ПОСТОЯННО(99%) | СИММЕТРИЧНО(1.04) | ИМЯ:PROXYWARE
                                      * ЗАДАЧА ПЛАНИРОВЩИКА: \WProxy\Repocket
                                      * первое появление: 2026-06-19 20:58:00
                                      * пользователь: user
```

`^` — поведенческие признаки из SRUM. `*` — обогащение из реестра.

### Признаки

| Метка | Условие | Что означает |
|---|---|---|
| `ПОСТОЯННО` | активен ≥90% часовых слотов | не останавливается — сервис, а не приложение |
| `СИММЕТРИЧНО` | 0.8 ≤ sent/recv ≤ 1.25 при sent > 50 МБ | машина не потребляет данные, а пропускает сквозь себя |
| `ОТДАЧА>ПРИЁМ` | sent/recv > 1.5 при sent > 20 МБ | выгрузка наружу |
| `ИМЯ:PROXYWARE` | совпало со списком проксивари | подсказка, не доказательство |
| `ИМЯ:TUNNEL` | совпало со списком туннелей | то же |
| `ПУТЬ:USER` | запуск из Users / Temp / Downloads / Desktop | софт мимо установщика |

**Поведенческие признаки первичны, имена вторичны.** Списки устареют, а «работает круглосуточно и sent≈recv» не устареет. Если бы проксиварь называлась `svchost_helper.exe`, первые три критерия всё равно бы сработали.

### Порог интереса

Три признака сразу и объём в сотни МБ → разбирать. Один признак или мелкий объём → почти всегда шум.

### Известный шум

| Что | Почему в выводе | Почему не оно |
|---|---|---|
| `nvidia overlay.exe` | 100% времени, ratio ~0.9 | 99 МБ за два месяца, подписанный вендор |
| игровые лаунчеры | симметричный трафик | P2P-раздача контента — механика, а не проксирование |
| апдейтеры (Kontur, Google) | 95% времени | единицы мегабайт |
| `Dnscache`, `System\IPv6 Control Message` | всегда активны | системные |

### `<AppId=1 unattributed>`

Строка с огромными объёмами — **не приложение**. У AppId=1 пустой `IdBlob`, это агрегированный неатрибутированный трафик. Скрипт помечает её явно. Не интерпретируй.

## 5. Что дают кусты

**SYSTEM:**
- часовой пояс машины → колонка локального времени в `--window`
- буква тома → `\device\harddiskvolume3\...` превращается в `C:\...`
- службы → зарегистрирован ли бинарь как служба и с каким `Start`

**SOFTWARE:**
- SID → имя пользователя
- задачи планировщика → частый механизм персистентности, когда службы и `Run` пусты
- установленные программы с `InstallDate` и `InstallLocation`
- ключи `Run` / `RunOnce`
- профили сетей с датами подключений (`--persistence`)

**NTUSER.DAT:**
- ключи `Run` пользователя
- **UserAssist** — счётчик GUI-запусков и время последнего. Отличает «прилетело с другим софтом» от «запускал руками». Для разбирательства об умысле это ключевой артефакт.

---

## 6. Ограничения

**SRUM сбрасывает данные раз в час.** Последние 60 минут перед снятием копии в базе могут отсутствовать. Пусто ≠ не было.

**Глубина 30–60 дней.** База ротируется, старые записи удаляются.

**Нет привязки DNS → процесс.** SRUM учитывает байты по приложениям, но не домены. Связку «какой процесс резолвил домен X» он не даёт. Для этого нужен Sysmon ID 22.

**SSID не определяется.** Подключи `WlanSvc\Interfaces\...\Profiles` в кусте пустые, маппинг `L2ProfileId → SSID` не работает — в отчёте показываются сырые числа. Вместо этого смотри `--persistence`, там `NetworkList\Profiles` даёт имена сетей с датами.

**Маппинг томов только системный.** `harddiskvolume3 → C:` выводится по расположению `\windows\system32`. Остальные тома (флешки, второй диск) остаются как есть.

**Списки имён неполные и устаревают.** `PROXYWARE` и `TUNNEL` в начале файла — дополняй под свою практику.

## 7. Настройка под себя

В начале файла:

```python
PROXYWARE = ['repocket', 'geonode', 'honeygain', ...]   # провайдеры residential-прокси
TUNNEL    = ['ngrok', 'cloudflared', 'frpc', ...]       # туннели и VPN
USER_DIRS = ['\\users\\', '\\temp\\', ...]              # пользовательские каталоги
USER_DIRS_SKIP = [...]                                  # известный системный шум
```

Пороги признаков — в функции `report()`:

```python
if cover >= 0.90:                                  # порог "ПОСТОЯННО"
if 0.8 <= ratio <= 1.25 and sent > 50_000_000:     # порог "СИММЕТРИЧНО"
if ratio > 1.5 and sent > 20_000_000:              # порог "ОТДАЧА>ПРИЁМ"
if sent + recv < 1_000_000: continue               # отсечка мелочи
```

Имена с `.exe` в списках матчатся по границе имени файла — иначе `locator.exe` ловится как `tor.exe`.

---

## 8. Типовой порядок работы

1. `--persistence` — что вообще стоит на машине и как закрепляется
2. общий отчёт — кто из этого реально ходит в сеть и с каким профилем трафика
3. `--app <имя>` по каждому кандидату — таймлайн и привязка к персистентности
4. `--window` вокруг интересующего события — что было активно в этот час

---

## 9. Если что-то падает

| Симптом | Причина |
|---|---|
| `Registry Parse Exception (Invalid REGF ID)` | файл не куст реестра или повреждён при передаче |
| `[!] SYSTEM не открылся` | скрипт продолжит без обогащения, не критично |
| время в отчёте на час-два мимо | проверь `ActiveTimeBias` в `SYSTEM\ControlSet00N\Control\TimeZoneInformation` |
| `первое появление: н/д` | бинаря нет в таблице Application Resource Usage — норма для короткоживущих процессов |
| пустой вывод в `--window` | время задаётся в UTC, не в локальном |

Ошибки открытия кустов не фатальны — скрипт печатает предупреждение и работает дальше только по SRUM.
